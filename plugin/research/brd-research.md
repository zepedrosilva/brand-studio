# Brand-kit research brief
Date: 2026-11-18. Scope researched: a plugin that turns a free-text narrative into a logo mark, lettering, a lockup, an icon set and a one-page brand sheet, written as SVG by the LLM with a script layer for validation, text-to-outline, tracing and export; plus a review mode that checks an SVG logo against craft rules. Audience: a developer making side-project or internal-tool identities, not a professional identity replacement. Kit code `brd`.

Method note: all product claims below were read from pages fetched during this research (2026-11-18) unless marked "snippet only" (search-result summary, page not opened) or "secondary". Third-party skill content was read as data; nothing was installed or run.

## TL;DR
- It already exists, and well. A 7.3k-star MIT Claude skill (kaankiziltug/logo-design-skill) does brief, concepts, 16 px and one-colour tests, an SVG audit script and a checkpoint. LogoLoom (MCP, MIT) does LLM-written SVG plus text-to-path, svgo and a 31-file kit. "LLM writes an SVG logo" is not a gap. The gaps are listed below.
- Core stance for our kit: concept before pixels, geometry before decoration, tests before showing. The LLM drafts primitives-first SVG, a script layer proves it (parse, render, small-size, one-colour, contrast, structure), and a human picks at a hard checkpoint. Legal items are warned about, never decided.
- Biggest gaps vs existing tools: (1) a narrative-to-concept method (narrative to essence, archetype, metaphor shortlist) that existing skills mostly replace with a questionnaire; (2) wordmark/lettering done properly (shaped, kerned outlines from an OFL font, or custom paths) because every source says live text or LLM-drawn letterforms fail; (3) a review mode with citable rule IDs, severities and detect methods (existing audits give a 0-100 score and heuristics, not rule catalogues); (4) a legal-warnings block (AI-art copyright, trademark similarity, font licences) that none of the skills surfaces beyond a line.
- LLM SVG is reliable for flat geometric marks with few shapes and degrades fast with complexity; text, symmetry, stacking order and path bloat are the failure modes; render-and-critique loops with vision are the working mitigation.

## Where the evidence changed the initial scope
1. "Research whether it exists": it does, in at least eight Claude skills and several MCP servers. The scope's workflow archetype (narrative to brief to concepts to SVG to sheet) is the common shape of existing skills, so the kit must differentiate on method and checks, not on the pipeline.
2. "No raster model required; LLM writes SVG directly": supported for simple marks (LogoLoom, neonwatty, kaankiziltug all do it), but the evidence says text and complex paths are weak, and the working fix is a vision-capable render-and-critique loop (Chat2SVG, IntroSVG, Render-in-the-Loop). kaankiziltug's skill says it works best with a model that can view images. A native-vector API (Recraft V3/V4.1 vector, QuiverAI Arrow 1.1) is a legitimate optional engine; it is paid and has licence terms that depend on plan. Recommend "no raster model required; image-capable model strongly recommended; hosted vector model optional".
3. "Out of scope: trademark clearance advice": agreed, but the kit should still include a similarity-risk warning and a pointer to the USPTO image-search beta (April 2026), because the common failure is generic lookalike marks (kaankiziltug's own log: 4 of 10 batch logos sent back for resembling earlier ones, a spinner, a play button).
4. "Brand sheet with clear space, minimum size, misuse" is standard practice (rknall skill, Looka, Brandmark), but only SVG Genie claims dark-variant automation; the one-page sheet is a reasonable fit for a developer audience. The neonwatty author warns this is not a replacement for brand strategy.
5. potrace and vtracer as tracing tools: only needed if a raster source exists (a diffusion image or a user-supplied PNG). With no raster model in the flow, tracing is an edge path, not core. Also potrace is GPL-2.0+ and its last release is 2019; vtracer is MIT but pip/npm/cargo packages are 1.0.0-alpha.4.

## Candidate principles and rule families
Principles (5 to 8):
1. Concept before drawing: one idea, statable in one sentence, chosen from a metaphor shortlist built from the narrative (A9, A27).
2. Black first: a mark must work in one colour, at 16 px, and reversed before colour or effects are added (A9, A10).
3. Primitives first, paths second: construct from circles, rects and arcs on a grid; add paths only for merged silhouettes (A2, kaankiziltug construction rules).
4. Prove, do not trust: every LLM-written SVG goes through parse, render and structural checks, then a vision critique, before a human sees it (A2, A3, A7).
5. Letters are outlines: no live text in masters; wordmarks are shaped, kerned outlines from an OFL font or custom paths (A12, A23, A24).
6. One checkpoint, then the kit: show three greyscale concepts and a recommendation; produce colour, lockups, icons and sheet only after a pick (A9).
7. Edit, do not regenerate, once a direction works (A10).
8. Warn, do not decide: copyright, trademark and font licence questions are surfaced with sources and left to the user (A12, A14, A16).

Rule families (reuse first): DEC (the brief and declaration block), CTR (SVG file contract), CAP (budgets: colours, nodes, minimum sizes, file size), SEC (SVG safety: no scripts, no external refs), EVD (findings that need a render or a live search). New families proposed: CRF (logo craft), TYP (lettering and fonts), CNC (concept method), LGL (legal warnings), SET (icon-set consistency).

## Technology differences
- LLM-written SVG versus hosted native-vector models (Recraft, QuiverAI): the first is free, deterministic enough with checks and full-ownership; the second gives better text placement (Recraft `text_layout`) and organic shapes but costs per image, varies in rights by plan, and adds cloud dependency. Quiver says long detailed SVGs that stay clean are an open problem.
- Diffusion then trace (potrace, vtracer, Vectorizer.AI): potrace is binary only and GPL; vtracer is colour capable and MIT but alpha-packaged; Vectorizer.AI is paid. Comparisons found are listicles or vendor blogs, with no independent benchmark; one vendor claims about 180 nodes against about 1,400 for potrace (biased, unverified). Tracing a raster logo yields node bloat and lost geometry; prefer primitives-first.
- Text to path: opentype.js (JS, MIT, kerning on, ligatures only liga and rlig, no complex scripts) versus fontTools plus uharfbuzz (Python, full shaping, more setup) versus Inkscape CLI. Latin wordmarks on opentype.js are acceptable; anything with complex scripts needs HarfBuzz.
- Rendering: resvg (Rust, no native text; deterministic, which is good for tests), rsvg-convert, cairosvg and headless Chromium differ on text and filters; test against two renderers or restrict features.
- svgo v3 versus v4: v4 preset-default does not include removeViewBox; v4.1.0 rejects some malformed XML that older versions accepted, so repair LLM output before optimising and record the version.
- Contrast: logo text is exempt from WCAG 1.4.3, but UI text on brand colours is not; kit should check both separately.
- Icon grids: Material 24 dp keylines and Lucide or Heroicons 24 grid with 1.5 or 2 px strokes are conventions, not standards. Material guidance fetched only as a headline summary; read the live page before quoting numbers.
- Jurisdictions: US human-authorship rule is the only one researched. EU, UK and others were not researched.

## Design questions the research raised
Each was decided in favour of the recommendation given; the decision records in the repository's `docs/decisions/` hold the reasoning.

1. Differentiation: given the crowded field, should the kit lead with (a) the narrative-to-concept method and (b) a rule catalogue with a review mode, rather than a new generator? I recommend yes, because those are the unfilled gaps and the generation pipeline is commodity.
2. Engine: LLM-only SVG with an image-capable model for critique, with a hosted vector model (Recraft or Quiver) as an optional adapter? I recommend LLM-only by default and no hosted dependency in v1, so licences stay simple.
3. Wordmarks: outlined OFL font only in v1, with custom lettering marked "needs a designer"? I recommend yes. Which two or three OFL families should the kit ship guidance for (check licences at build)?
4. Script language: the repo scripts are shell and Python; kaankiziltug's tools are Python stdlib only plus an external renderer; LogoLoom is Node. I recommend Python 3 stdlib for checks, with resvg or rsvg-convert as an optional renderer and svgo as an optional optimiser.
5. Concept count and checkpoint: three greyscale concepts at a hard checkpoint (kaankiziltug pattern)? I recommend yes.
6. Legal block: warnings only, US-centred, with a note that other jurisdictions were not researched. Add EU or UK research later? I recommend later, only if you plan to register a mark.
7. Review mode input: SVG files only, or also PNG (needs tracing or vision-only review)? I recommend SVG only, with a PNG fallback that gives a vision-only, lower-confidence review.
8. Licence of borrowed material: all ideas above are paraphrased; kaankiziltug, op7418, neonwatty and LogoLoom are MIT, so structure can be borrowed with attribution if you want text reuse; rknall, jezweb, nasrulhazim and inbharatai state no licence, so paraphrase only.

- Primary books (Rand essay, Wheeler, Mark and Pearson) not read; craft rules are labelled practitioner opinion for that reason.
- Papers A3 to A6 are search-snippet level; A1 was read for 100k of 121k characters.
- Adobe, Looka, Canva, Brandmark and Figma claims come from search summaries and review sites, not their own terms pages (except Canva and Recraft rights, which cite the vendor help or docs pages by the search tool's summary).
- No independent test of Vectorizer.AI versus potrace versus vtracer was found.
- No logo-specific LLM benchmark was found; evidence is for icons and general SVG.
- Star counts and "last commit" dates for most third-party repos were not visible on fetched pages.
